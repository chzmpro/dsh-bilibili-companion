## §2 🔴 AI 身份：直接对立

| 来源 | 原文 |
|---|---|
| **13 号 §5.3（B8 甲）** | `❌ 不提"我是 AI"` |
| **任务书 §6.4** | "小号**可适度**表明 AI 身份，语气自然，不重复模板" |

### 分析

- 任务书用"**可**"，是**许可**，不是**要求**；
- 13 号用"❌ 不提"，是**你的硬性指令**。

**两者并不真正互斥**（一个允许、一个收窄），但**气质上相反**：
任务书整篇假设"公开评论是外部写入"，倾向于**诚实标注 AI** 以避免"冒充真人"的指责
（它还明写"不得…**冒充真人观众**"）；而你要的是**低调、不暴露**。

### 我的判定

**采用 13 号：不提 AI 身份。** 因为：
1. 它是你明确的选择（问卷 B8 甲）；
2. 任务书的"可"只是允许，不采纳不等于违规；
3. 但任务书那句"**不得冒充真人观众**"仍需遵守 —— 我把它落成
   **"不主动声明、也不伪装成真人"**：不说"我是 AI"，也不去假装自己是人类观众
   （不编造"我昨天试了"这类真人经历）。

### 选项

| 选项 | 说明 |
|---|---|
| **A（建议）** | 不提 AI，但不伪装真人经历（不编造个人体验） |
| B | 按任务书"适度表明 AI 身份"（更透明，但偏离你的 B8 甲） |

## §7 后续已消解的冲突（2026-10-15 更新）

### ✅ `@` 提及：不再需要浏览器

**原冲突**：任务书说"`@` 要检查**页面渲染后的 UID**"，
但又明令"定时 preset **不给**通用浏览器" —— 两条要求看起来无法同时满足。

**消解方式**：实测发现 B站把"这条评论 @ 到了谁"作为**服务端事实**放在
评论对象的 `content.members[]` 里，**读接口就能拿到**：

```
真机验证（BV1nFp46qECm）
  核验真被 @ 的人   → verified ✅
  核验没被 @ 的主号 → failed（并报出实际 @ 到谁）✅
```

→ **用纯 API 核验**，不需要浏览器。任务书那句"若 API 无法可靠表达"
现在**不适用**，因此两条约束都满足。

> ⚠️ 但要注意：**B站按「昵称」匹配提及**，写 `@数字UID` 不产生提醒。
> 所以 `owner_name_hint` 从"可选提示"变成**必需项**；
> 缺它时状态记 `unsupported`（如实汇报，不假装成功）。
