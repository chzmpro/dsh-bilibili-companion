# 自动轮恢复与跨平台只读设计

用户已确认上轮审查中的实施路线：修复投递恢复和完成判定，接入小红书、抖音读取，再通过 Fork PR 交付。公开互动与原生私信不在本轮接入范围。

## 保持的契约

- 默认只启用 B 站，现有 BV 主键、笔记、证据和发布配额不变。
- 外部后端由用户独立部署、登录；本项目不安装、复制签名算法或处理验证码。
- 外部工具采用只读白名单，不透传其发评、点赞、私信工具给 DSH。
- 原文进入本地证据和豆包，MCP 只返回短包；值班会话沿用已有 2500 规则。

## 两个独立子项目

### 自动轮

保存已整理的投递包，失败后恢复同一包而非丢候选或再次调用豆包。确定未接收和接收不确定分别处理，后者不盲重发。只有与本次投递关联的 DSH 处理完成才记成功。调度区分成功和失败，失败恢复有间隔和次数上限；保存调度配置后下次 tick 生效。

### 跨平台读取

小红书通过外部 HTTP MCP，抖音通过外部 stdio MCP。使用项目现有 SDK；运行时构造不启动网络或子进程。规范化搜索、详情、正文/字幕/ASR及评论，持久保存详情访问上下文。

保留现有 videos/evidence/notes 关系，外部内容使用命名空间主键，并增加平台、账号、原生 ID 映射。缓存及读取健康状态按平台/账号隔离。缺登录、验证码、限流必须显式记录，人工恢复前不继续请求；不得将异常伪装为空结果。

图文笔记可选本地 Tesseract OCR，保留图片页码和来源，不将 OCR 识别当作人工看过图片。未安装或识别失败如实降级，不使用只懂文字的豆包识图。所有外部公开写入均拒绝。

## 验收

隔离测试覆盖投递失败重启恢复、失败调度、跨任务完成误判、动态配置、真实上游返回形状规范化、跨平台同 ID、访问上下文重启、证据摘录、短包预算、缓存/风控隔离、OCR页码和缺依赖、外部写入拒绝、MCP/CLI可达性。通过完整 pytest、Ruff、mypy、插件自检；真实账号联调与真实 token 消耗另标为未验证。
